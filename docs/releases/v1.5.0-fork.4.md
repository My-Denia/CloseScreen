# CloseScreen v1.5.0-fork.4

## Rust native capture is now the Windows default

This is the first public CloseScreen release built from the completed Rust-default Windows native
capture migration. Rust now provides the packaged Windows x64 WGC video, WASAPI audio, webcam
sidecar, and cursor-helper path by default.

The legacy C++ capture and cursor helpers remain packaged as an explicit rollback pair. Set the
environment variable before launching CloseScreen:

```powershell
$env:CLOSESCREEN_WINDOWS_CAPTURE_BACKEND = "legacy"
```

An unset selector chooses Rust. Invalid values fail explicitly, and a recording does not silently
switch backend after startup.

The Electron main process, renderer, recording session, editor, and MP4/GIF export architecture are
unchanged by this migration.

## Capture and export validation

The Rust-default packaged application passed real UI-level smoke validation on the maintainer's
single-display Windows x64 laptop:

- CloseScreen launched as a normal user and selected the Rust backend by default.
- Recording, normal UI stop, Electron-managed finalization, and editor loading completed.
- Recognizable system audio was present in the source recording. MP4 export preserved non-zero,
  decodable 48 kHz stereo AAC, and GIF export completed as the expected video-only format.
- A spoken microphone recording was audible in the source and remained audible after MP4 export.
  The exported AAC stream contained 694 packets and was non-empty and non-silent.
- USB webcam preview and recording completed through the application. The exported 13.13-second,
  1920x1080 H.264 MP4 visibly retained the webcam picture-in-picture.
- MP4 export completed through the native Windows save dialog.

The packaged legacy UI path was not repeated during this release-validation round and is therefore
`NOT VERIFIED`, not failed. The explicit
`CLOSESCREEN_WINDOWS_CAPTURE_BACKEND=legacy` rollback remains packaged and available.

Earlier Realtek microphone and USB webcam deadline observations came from direct helper invocation
with a fixed nine-second post-stop deadline. They did not reproduce through the packaged
Electron-managed lifecycle and are classified as test-contract false negatives relative to the
product path. They are not demonstrated CloseScreen product defects, hardware limitations, or
release blockers.

At the deterministic helper/contract layer, the Rust and legacy paths remain covered by parity,
bounded shutdown, fault-injection, timestamp, audio-timeline, webcam-sidecar, cursor, and
packaged-payload checks where the available Windows environment can exercise them. Helper-level
parity does not substitute for packaged legacy UI validation.

The Windows release gate requires real media evidence, not track metadata alone. System-audio
checks require a 48 kHz stereo AAC stream with non-zero packets, decodable frames, and aligned
duration. A native recording must load in the editor; MP4 export must retain decodable AAC; GIF
export remains video-only.

## Release targets and build trust

- Windows x64: unsigned NSIS installer containing the Rust-default and legacy rollback helper pairs.
- Linux: unsigned AppImage, deb, and pacman artifacts using the existing Electron/browser capture
  path.
- macOS: not a current release target; this release does not include a macOS artifact.
- Windows ARM64: not a current release target.

These builds are unsigned and can trigger SmartScreen, unknown-publisher, executable-bit, or
package-trust prompts.

Release qualification is limited to one Windows x64 laptop with a single display. It does not
establish multi-monitor behavior, Linux desktop runtime behavior, macOS, ARM64, external audio or
camera matrices, broad GPU/vendor driver coverage, signing, or notarization. Hardware-dependent
paths that cannot be exercised are recorded as `NOT VERIFIED`, not inferred as supported.

## Packaging integrity

The tag-triggered release workflow verifies the tag/package version contract, builds from the
tagged commit, records Windows and Linux provenance, stages unique final asset names, generates
`SHA256SUMS.txt` from those names, and verifies the checksums before upload.

```text
resources/licenses/README.md

```
